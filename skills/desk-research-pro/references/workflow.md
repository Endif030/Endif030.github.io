# 桌面研究详细工作流程

## Phase 1: 需求确认与框架设计 (30-60分钟)

### Step 1: 需求澄清会议

**必问问题清单**:

1. **研究主题**
   - 报告核心主题是什么？
   - 研究对象是谁？（行业/公司/产品）
   - 研究目的是什么？（投资决策/战略规划/竞品分析）

2. **研究范围**
   - 时间范围？（历史/现状/预测）
   - 地域范围？（中国/全球/特定区域）
   - 细分领域？（全产业链/特定环节）

3. **关键问题**
   - 核心要回答的问题是什么？
   - 关键指标有哪些？（市场规模/增速/竞争格局）
   - 决策需要哪些信息支撑？

4. **交付物**
   - 完整报告？PPT？还是数据表？
   - 页数/篇幅要求？
   - 截止日期？

**输出**: 需求确认文档

---

### Step 2: 研究框架设计

**标准研究维度**:

```
1. 执行摘要
   - 核心发现
   - 关键数据
   - 主要结论

2. 发展历程
   - 行业发展阶段
   - 关键里程碑
   - 驱动因素

3. 市场现状
   - 市场规模
   - 增长速度
   - 市场结构

4. 竞争格局
   - 主要玩家
   - 市场份额
   - 竞争特征

5. 商业模式
   - 盈利模式
   - 成本结构
   - 定价策略

6. 用户画像
   -  demographics
   - 消费行为
   - 需求特征

7. 产业链
   - 上游供应
   - 中游运营
   - 下游消费

8. 政策法规
   - 监管政策
   - 行业标准
   - 政策趋势

9. 前景机会
   - 增长驱动
   - 市场机会
   - 趋势预测

10. 风险提示
    - 行业风险
    - 投资建议
```

**根据主题调整维度**:
- B2B行业：增加企业客户分析
- 消费品：加强用户画像和品牌分析
- 新兴市场：强调教育和市场培育

**输出**: 研究框架文档

---

### Step 3: 获取用户确认

**必须获得明确确认**:
- "以上研究框架是否符合您的需求？"
- "是否有需要调整或补充的维度？"
- "确认后我将开始资料收集工作"

### Step 5: 执行资料收集

**使用 Tavily API**:

```python
import requests
import json

def tavily_search(query, max_results=8):
    url = "https://api.tavily.com/search"
    headers = {"Content-Type": "application/json"}
    payload = {
        "api_key": TAVILY_API_KEY,
        "query": query,
        "search_depth": "advanced",
        "include_answer": True,
        "max_results": max_results
    }
    response = requests.post(url, json=payload, headers=headers)
    return response.json()
```

**收集标准**:
- 每个维度至少5-10条来源
- 优先权威来源（行业协会、知名研究机构）
- 保留原始链接和内容摘要
- 记录收集时间

**分类结构**:

```json
{

```

**整理步骤**:
1. 去重（同一来源只保留一次）
2. 分类（按研究维度归类）
3. 摘要（提取关键信息）
4. 评级（评估可信度）

---

### Step 7: 识别数据缺口

**数据缺口清单模板**:

| 缺失数据 | 重要程度 | 影响 | 获取建议 |
|----------|---------|------|----------|
| XXX | ⭐⭐⭐⭐⭐ | 无法估算市场规模 | 行业协会、券商研报 |
| YYY | ⭐⭐⭐ | 影响竞争分析深度 | 企业财报、天眼查 |

**标记方式**:
- 在报告中使用 ⚠️ 标注
- 说明缺失原因
- 提供获取建议

---

## Phase 3: 分析与报告撰写 (4-6小时)

### Step 8: 数据分析

**分析维度**:
1. **横向对比**（中美/竞品对比）
2. **纵向趋势**（历史变化）
3. **结构分析**（市场份额/产业链）
4. **因果分析**（驱动因素/制约因素）

**估算方法**:
- 类比估算：参考相似市场
- 自上而下：从整体推算局部
- 自下而上：从局部加总整体
- 专家判断：基于经验估算

**注意**: 估算数据必须明确标注

---

### Step 9: 撰写完整报告

**写作规范**:

1. **数据来源标注**
   - 每条数据后注明来源
   - 格式：`(数据来源: XXX)`
   - 首次引用详细标注，后续可简化

2. **数据缺口标注**
   - 使用 ⚠️ 符号
   - 说明："⚠️ 该数据暂未找到权威来源"

3. **估算数据标注**
   - 使用 "约"、"估算"、"推测"
   - 说明估算逻辑

4. **图表使用**
   - 数据表格化呈现
   - 对比分析可视化
   - 趋势变化图表化

**报告章节撰写要点**:

| 章节 | 重点 | 常用数据 |
|------|------|----------|
| 执行摘要 | 3-5个核心发现 | 市场规模、增速、主要结论 |
| 发展历程 | 关键节点、阶段划分 | 时间节点、里程碑事件 |
| 市场现状 | 规模、增速、结构 | 绝对值、增长率、占比 |
| 竞争格局 | 主要玩家、份额 | CR5、排名、差异化 |
| 商业模式 | 盈利方式、成本 | 毛利率、费用结构 |
| 用户画像 |  demographics、行为 | 年龄、收入、频次 |
| 产业链 | 上下游、价值分布 | 各环节占比、利润率 |
| 前景机会 | 增长驱动、机会点 | 预测数据、渗透率 |
| 风险提示 | 主要风险、应对 | 风险等级、案例 |

---

### Step 10: 制作PPT

**PPT结构（15页）**:

1. 封面
2. 目录
3. 核心发现（1-2页）
4. 市场现状（2-3页）
5. 竞争格局（1-2页）
6. 商业模式（1-2页）
7. 用户画像（1页）
8. 前景机会（1页）
9. 风险提示（1页）
10. 投资建议（1页）
11. 核心数据（1页）
12. 结束页

**设计规范**:

```python
# 配色方案
COLORS = {
    "primary": RGBColor(0, 51, 102),      # 深蓝
    "secondary": RGBColor(255, 127, 39),   # 橙色
    "accent": RGBColor(0, 176, 80),        # 绿色
    "text": RGBColor(51, 51, 51),          # 深灰
    "light": RGBColor(128, 128, 128)       # 浅灰
}
```

**图表要求**:
- 柱状图：趋势对比
- 饼图：结构占比
- 条形图：排名对比
- 所有图表必须带数据标签

**数据来源标注**:
- 每页底部用小字标注
- 格式："数据来源: XXX"

---

## Phase 4: 交付与迭代 (30分钟)

### Step 11: 成果交付

**交付文件清单**:

1. **完整报告** (Markdown/PDF)
   - 文件名：`{主题}_研究报告_完整版.md`
   - 页数：30-50页
   - 包含：所有分析、数据、图表

2. **PPT演示版** (PPTX)
   - 文件名：`{主题}_研究报告_PPT版.pptx`
   - 页数：15-20页
   - 包含：核心发现、图表、结论

3. **资料库** (JSON)
   - 文件名：`{主题}_资料库.json`
   - 包含：所有原始资料、分类、摘要

4. **数据缺口清单** (Markdown)
   - 文件名：`{主题}_数据缺口.md`
   - 包含：缺失数据、重要程度、获取建议

---

### Step 12: 用户反馈与迭代

**收集反馈**:
- "报告内容是否符合预期？"
- "有哪些需要补充或调整的地方？"
- "数据缺口是否需要进一步补充？"

**迭代优化**:
- 根据反馈补充资料
- 调整报告结构
- 完善数据可视化
- 优化结论建议

## 常见问题

**Q: 找不到权威数据怎么办？**
A: 明确标注数据缺口，使用估算（说明逻辑），提供获取建议。

**Q: 数据来源冲突怎么办？**
A: 优先权威来源，注明差异，说明采用哪个及原因。

**Q: 用户要求调整框架怎么办？**
A: 根据反馈调整，重新确认后再继续。

**Q: 资料太多如何取舍？**
A: 优先权威来源、最新数据、直接相关的内容。
